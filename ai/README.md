# 在当前框架中使用游戏工作室模板

`Claude-Code-Game-Studios/` 用于参考游戏策划、迭代、审查和验收流程。
实际游戏沿用当前 Java 8 / Linux X11 / LWJGL / OpenGL 框架。

## 开始开发

从本仓库根目录启动开发会话，入口约定见根目录 `CLAUDE.md`。
给出目标游戏与本次目标，例如：

> 沿用当前框架，参考 ai/Claude-Code-Game-Studios 的轻量迭代流程，
> 为星隙竞技场改进一个指定功能，完成相关测试和画面验收。

或：

> 沿用当前框架新建游戏。先和我确定核心玩法，再形成简短策划，
> 然后在 packages/apps/ 下实现可玩的最小版本。

## 路径与执行约定

| 内容 | 本仓库位置 |
| --- | --- |
| 公共框架 | `base/` |
| 游戏代码、运行资源及游戏测试 | `packages/apps/<游戏>/`，遵循应用现有结构 |
| 现有游戏参考 | `packages/apps/rift-arena/README.md` |
| 原始素材与来源 | `external/` |
| AI 流程模板 | `ai/Claude-Code-Game-Studios/` |
| 构建与验证产物 | `out/` |

不要把模板自身的 `src/`、`assets/` 或 `tests/` 当作现有游戏目录。
对现有游戏的策划与开发记录优先保存在其应用目录中，避免混入模板的框架自测内容。

## 接入范围

目前接入的是项目说明与人工选择的工作流，尚未移植模板的 slash commands、
hooks、引擎注册表和路径校验。这些配置默认面向模板所在目录及其内置引擎。
在本仓库根目录输入 `/start` 或 `/prototype`，不保证能发现嵌套目录中的技能。

如以后需要完整命令集，应另行适配仓库根路径、自定义 Java/OpenGL 引擎、
应用构建命令、测试入口和规则匹配，并验证后再启用。
